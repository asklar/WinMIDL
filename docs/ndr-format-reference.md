# NDR Format String Reference for Proxy/Stub (_p.c) Generation

> **Purpose:** This document is the specification for implementing `StubEmitter` in our MIDL compiler.
> It documents the complete structure of a `_p.c` proxy/stub file as generated by Microsoft's `midl.exe`,
> the NDR type and procedure format string encodings, vtable layouts, and how our symbol model maps to
> these structures.
>
> **Sources:**
> - Generated reference files from `midl.exe` 8.01.0628 (Windows SDK 10.0.26100.0)
> - OS MIDL source at `E:\os\src\com\rpc\midl\codegen\` (format string generation, proxy/stub emission)
> - OS MIDL headers: `frmtstr.hxx`, `cgcommon.hxx`, `btcls.hxx`, `procndr.cxx`, `cgobject.cxx`

## 1. Overall _p.c File Structure

A proxy/stub file follows this exact section order:

```
┌─────────────────────────────────────────────────┐
│ 1. File header comment (compiler version, date) │
│ 2. #if defined(_M_AMD64) platform guard         │
│ 3. #pragma warnings and optimizations            │
│ 4. #define USE_STUBLESS_PROXY                    │
│ 5. #include "rpcproxy.h" + version check         │
│ 6. #include "<filename>.h"                       │
│ 7. Format string size #defines                   │
│ 8. Format string struct typedefs                 │
│ 9. RPC transfer syntax identifier                │
│ 10. XFG trampoline macros (CFG support)          │
│ 11. External declarations                        │
│ 12. PROC format string data                      │
│ 13. TYPE format string data                      │
│ 14. User marshal XFG trampolines + routines      │
│ 15. Per-interface sections (repeated):            │
│     a. Interface comment with GUID               │
│     b. FormatStringOffsetTable[]                  │
│     c. MIDL_STUBLESS_PROXY_INFO                  │
│     d. MIDL_SERVER_INFO                          │
│     e. CINTERFACE_PROXY_VTABLE (proxy vtable)    │
│     f. Stub function table (for delegating)      │
│     g. CInterfaceStubVtbl (stub vtable)          │
│ 16. MIDL_STUB_DESC (shared across interfaces)    │
│ 17. ProxyVtblList[] (all interfaces)             │
│ 18. StubVtblList[] (all interfaces)              │
│ 19. InterfaceNamesList[]                         │
│ 20. BaseIIDList[] (for delegating interfaces)    │
│ 21. IID_Lookup function                          │
│ 22. ExtendedProxyFileInfo struct                 │
│ 23. #pragma warning(pop) + #endif                │
└─────────────────────────────────────────────────┘
```

### Key #defines

```c
#define TYPE_FORMAT_STRING_SIZE   113    // byte count of type format string
#define PROC_FORMAT_STRING_SIZE   449    // byte count of proc format string
#define EXPR_FORMAT_STRING_SIZE   1      // usually 1 (unused)
#define TRANSMIT_AS_TABLE_SIZE    0
#define WIRE_MARSHAL_TABLE_SIZE   1      // number of user-marshal types (e.g., HSTRING)
```

### Format String Struct Typedefs

```c
typedef struct _<filename>_MIDL_TYPE_FORMAT_STRING {
    short          Pad;
    unsigned char  Format[ TYPE_FORMAT_STRING_SIZE ];
} <filename>_MIDL_TYPE_FORMAT_STRING;

typedef struct _<filename>_MIDL_PROC_FORMAT_STRING {
    short          Pad;
    unsigned char  Format[ PROC_FORMAT_STRING_SIZE ];
} <filename>_MIDL_PROC_FORMAT_STRING;

typedef struct _<filename>_MIDL_EXPR_FORMAT_STRING {
    long          Pad;
    unsigned char  Format[ EXPR_FORMAT_STRING_SIZE ];
} <filename>_MIDL_EXPR_FORMAT_STRING;
```

The `Pad` field ensures the `Format` array is aligned. The struct is initialized with `Pad = 0`.

### Naming Convention (from `cgcommon.hxx`)

| Concept | C Name Pattern | OS Source Name |
|---------|---------------|----------------|
| Type format string struct | `<file>__MIDL_TypeFormatString` | `FORMAT_STRING_STRUCT_NAME` |
| Proc format string struct | `<file>__MIDL_ProcFormatString` | `PROC_FORMAT_STRING_STRUCT_NAME` |
| Format string offset table | `<Iface>_FormatStringOffsetTable` | `FORMAT_STRING_OFFSET_TABLE_NAME` |
| Server info | `<Iface>_ServerInfo` | `SERVER_INFO_VAR_NAME` |
| Proxy info | `<Iface>_ProxyInfo` | `MIDL_PROXY_INFO_VAR_NAME` |
| Stub desc | `Object_StubDesc` | `STUB_DESC_STRUCT_VAR_NAME` |

## 2. FC_* Format Character Constants

The `FORMAT_CHARACTER` enum defines all NDR type format codes. These are single-byte values embedded in the format strings.

### Base Types (Primitives)

| Value | Name | Size | WinRT Type |
|-------|------|------|------------|
| `0x01` | `FC_BYTE` | 1 | `UInt8` |
| `0x02` | `FC_CHAR` | 1 | `Char16` (rarely) |
| `0x03` | `FC_SMALL` | 1 | `Boolean` (WinRT boolean = 1 byte) |
| `0x04` | `FC_USMALL` | 1 | (unsigned small) |
| `0x05` | `FC_WCHAR` | 2 | `Char16` |
| `0x06` | `FC_SHORT` | 2 | `Int16` |
| `0x07` | `FC_USHORT` | 2 | `UInt16` |
| `0x08` | `FC_LONG` | 4 | `Int32`, `HRESULT` |
| `0x09` | `FC_ULONG` | 4 | `UInt32` |
| `0x0A` | `FC_FLOAT` | 4 | `Single` |
| `0x0B` | `FC_HYPER` | 8 | `Int64`, `UInt64` |
| `0x0C` | `FC_DOUBLE` | 8 | `Double` |
| `0x0D` | `FC_ENUM16` | 2 | (16-bit enums) |
| `0x0E` | `FC_ENUM32` | 4 | WinRT enums (Int32/UInt32 underlying) |
| `0x0F` | `FC_IGNORE` | - | (ignore pointer) |
| `0x10` | `FC_ERROR_STATUS_T` | 4 | (error_status_t) |

### Pointer Types

| Value | Name | Description |
|-------|------|-------------|
| `0x11` | `FC_RP` | Reference pointer (non-null, stack-allocated target) |
| `0x12` | `FC_UP` | Unique pointer (nullable, heap-allocated) |
| `0x13` | `FC_OP` | Object pointer (OLE object reference) |
| `0x14` | `FC_FP` | Full pointer (aliasing allowed) |

**Pointer flags** (second byte after FC_RP/FC_UP/FC_OP):

| Flag | Hex | Meaning |
|------|-----|---------|
| `alloced_on_stack` | `0x04` | Target is stack-allocated |
| `simple_pointer` | `0x08` | Points to a simple base type (next byte is the FC_* type) |
| `pointer_deref` | `0x10` | Double indirection (pointer to pointer) |

**Examples from generated code:**
```c
0x11, 0xc,   /* FC_RP [alloced_on_stack] [simple_pointer] */  → for out INT32*
0x11, 0x4,   /* FC_RP [alloced_on_stack] */                   → for out HSTRING*
0x11, 0x10,  /* FC_RP [pointer_deref] */                      → for out IInspectable**
0x11, 0x0,   /* FC_RP */                                      → for in GUID (by ref)
0x12, 0x0,   /* FC_UP */                                      → unique pointer to BSTR wire repr
0x13, 0x0,   /* FC_OP */                                      → object pointer in wire repr
```

### Structure Types

| Value | Name | Description |
|-------|------|-------------|
| `0x15` | `FC_STRUCT` | Simple structure (no pointers, no conformance) |
| `0x16` | `FC_PSTRUCT` | Structure with pointers |
| `0x17` | `FC_CSTRUCT` | Conformant structure (trailing conformant array) |
| `0x18` | `FC_CPSTRUCT` | Conformant structure with pointers |
| `0x19` | `FC_CVSTRUCT` | Conformant varying structure |
| `0x1A` | `FC_BOGUS_STRUCT` | Complex structure requiring special handling |

### Array Types

| Value | Name | Description |
|-------|------|-------------|
| `0x1B` | `FC_CARRAY` | Conformant array (size determined at runtime) |
| `0x1C` | `FC_CVARRAY` | Conformant varying array |
| `0x1D` | `FC_SMFARRAY` | Small fixed array (size ≤ 65535) |
| `0x1E` | `FC_LGFARRAY` | Large fixed array |
| `0x21` | `FC_BOGUS_ARRAY` | Complex array |

### Special Types

| Value | Name | Description |
|-------|------|-------------|
| `0x2F` | `FC_IP` | Interface pointer |
| `0x4C` | `FC_EMBEDDED_COMPLEX` | Embedded complex type in a structure |
| `0x5A` | `FC_CONSTANT_IID` | Constant IID follows (16 bytes) |
| `0x5B` | `FC_END` | End of type description |
| `0x5C` | `FC_PAD` | Padding byte for alignment |
| `0xB4` | `FC_USER_MARSHAL` | User-marshalled type (HSTRING, BSTR) |
| `0xB7` | `FC_RANGE` | Range-constrained type |
| `0xB8` | `FC_INT3264` | Platform-dependent 32/64-bit int |
| `0xB9` | `FC_UINT3264` | Platform-dependent unsigned 32/64-bit int |

### Handle Types (used in procedure headers)

| Value | Name | Description |
|-------|------|-------------|
| `0x30` | `FC_BIND_CONTEXT` | Context handle binding |
| `0x31` | `FC_BIND_GENERIC` | Generic binding handle |
| `0x32` | `FC_BIND_PRIMITIVE` | Primitive binding handle |
| `0x33` | `FC_AUTO_HANDLE` | Automatic handle (standard for COM) |
| `0x34` | `FC_CALLBACK_HANDLE` | Callback handle |

### Procedure Parameter Tokens (V1/Old-style)

| Value | Name | Description |
|-------|------|-------------|
| `0x4D` | `FC_IN_PARAM` | [in] complex parameter |
| `0x4E` | `FC_IN_PARAM_BASETYPE` | [in] base-type parameter |
| `0x4F` | `FC_IN_PARAM_NO_FREE_INST` | [in] no-free-inst parameter |
| `0x50` | `FC_IN_OUT_PARAM` | [in,out] parameter |
| `0x51` | `FC_OUT_PARAM` | [out] parameter |
| `0x52` | `FC_RETURN_PARAM` | return value (complex) |
| `0x53` | `FC_RETURN_PARAM_BASETYPE` | return value (base type) |

## 3. Type Format Strings

The type format string (`MIDL_TYPE_FORMAT_STRING`) describes the wire representation of all non-trivial types used across all interfaces in the file. Base types (like `FC_LONG`) are encoded inline in procedure format strings and don't need entries here.

### Structure: Starts with `NdrFcShort(0x0)` padding

```c
static const <file>_MIDL_TYPE_FORMAT_STRING <file>__MIDL_TypeFormatString = {
    0,       // Pad
    {
        NdrFcShort( 0x0 ),   // offset 0: padding/sentinel
        /* offset 2: first type description */
        ...
        0x0                  // terminator
    }
};
```

### Common Type Patterns

#### Simple pointer to base type (for `[out] INT32*`)
```c
/* offset */
    0x11, 0xc,    /* FC_RP [alloced_on_stack] [simple_pointer] */
    0x8,          /* FC_LONG */
    0x5c,         /* FC_PAD */
```
- `FC_RP` with flags `0x0c` (alloced_on_stack | simple_pointer)
- Next byte: the base type format char
- `FC_PAD` for alignment

#### Simple pointer to base type (for `[out] boolean*`)
```c
    0x11, 0xc,    /* FC_RP [alloced_on_stack] [simple_pointer] */
    0x3,          /* FC_SMALL */
    0x5c,         /* FC_PAD */
```

#### Simple pointer to base type (for `[out] DOUBLE*`)
```c
    0x11, 0xc,    /* FC_RP [alloced_on_stack] [simple_pointer] */
    0xc,          /* FC_DOUBLE */
    0x5c,         /* FC_PAD */
```

#### Interface pointer (for `[out] IInspectable**`)
```c
    0x11, 0x10,   /* FC_RP [pointer_deref] */
    NdrFcShort( 0x2 ),  /* Offset= 2 (next entry) */

    0x2f,         /* FC_IP */
    0x5a,         /* FC_CONSTANT_IID */
    NdrFcLong( 0xaf86e2e0 ),  /* IID Data1 (as signed int32) */
    NdrFcShort( 0xb12d ),     /* IID Data2 */
    NdrFcShort( 0x4c6a ),     /* IID Data3 */
    0x9c, 0x5a,               /* IID Data4[0..1] */
    0xd7, 0xaa,               /* IID Data4[2..3] */
    0x65, 0x10,               /* IID Data4[4..5] */
    0x1e, 0x90,               /* IID Data4[6..7] */
```

Total: FC_RP (2 bytes) + offset (2 bytes) + FC_IP (2 bytes) + IID (16 bytes) = 22 bytes

#### HSTRING/BSTR (FC_USER_MARSHAL)

HSTRING and BSTR use `FC_USER_MARSHAL` with a wire representation as a conformant structure:

**Wire representation of HSTRING (same as BSTR):**
```c
    /* Unique pointer to BSTR/HSTRING wire struct */
    0x12, 0x0,    /* FC_UP */
    NdrFcShort( 0xe ),  /* Offset to FC_CSTRUCT */

    /* Conformant array of wchar_t */
    0x1b,         /* FC_CARRAY */
    0x1,          /* alignment = 1 */
    NdrFcShort( 0x2 ),  /* element size = 2 (wchar_t) */
    0x9,          /* Corr desc: FC_ULONG */
    0x0,
    NdrFcShort( 0xfffc ),  /* offset to length field = -4 */
    NdrFcShort( 0x1 ),     /* Corr flags: early */
    0x6,          /* FC_SHORT (element type) */
    0x5b,         /* FC_END */

    /* Conformant structure containing {length, alloc, data[]} */
    0x17,         /* FC_CSTRUCT */
    0x3,          /* alignment = 3 (4-byte aligned) */
    NdrFcShort( 0x8 ),    /* struct size = 8 (two longs) */
    NdrFcShort( 0xfff0 ), /* Offset back to FC_CARRAY = -16 */
    0x8,          /* FC_LONG (length field) */
    0x8,          /* FC_LONG (alloc field) */
    0x5c,         /* FC_PAD */
    0x5b,         /* FC_END */
```

**FC_USER_MARSHAL entry (for [in] HSTRING, passed by value):**
```c
    0xb4,         /* FC_USER_MARSHAL */
    0x83,         /* flags: 0x80 (unique) | 0x03 (alignment) */
    NdrFcShort( 0x0 ),    /* user marshal table index = 0 */
    NdrFcShort( 0x8 ),    /* user type memory size = 8 (pointer size on x64) */
    NdrFcShort( 0x0 ),    /* user type buffer size = 0 (variable) */
    NdrFcShort( 0xffde ), /* Offset to wire representation (FC_UP) */
```

**FC_USER_MARSHAL entry (for [out, retval] HSTRING*):**
A separate entry is needed because the `[out]` case uses `FC_RP [alloced_on_stack]` → `FC_OP` → wire struct,
while `[in]` uses `FC_UP` → wire struct directly.

```c
    0x11, 0x4,    /* FC_RP [alloced_on_stack] */
    NdrFcShort( 0x6 ),  /* Offset to FC_USER_MARSHAL */

    0x13, 0x0,    /* FC_OP (object pointer) */
    NdrFcShort( 0xffe6 ), /* Offset back to FC_CSTRUCT */

    0xb4,         /* FC_USER_MARSHAL */
    0x83,         /* flags */
    NdrFcShort( 0x0 ),    /* table index */
    NdrFcShort( 0x8 ),    /* memory size */
    NdrFcShort( 0x0 ),    /* buffer size */
    NdrFcShort( 0xfff4 ), /* Offset to FC_OP */
```

#### GUID Structure

```c
    0x11, 0x0,    /* FC_RP */
    NdrFcShort( 0x8 ),  /* Offset to FC_STRUCT */

    /* Small fixed array for Data4[8] */
    0x1d,         /* FC_SMFARRAY */
    0x0,          /* alignment = 0 */
    NdrFcShort( 0x8 ),  /* total size = 8 */
    0x1,          /* FC_BYTE (element type) */
    0x5b,         /* FC_END */

    /* GUID structure: { DWORD, WORD, WORD, BYTE[8] } */
    0x15,         /* FC_STRUCT */
    0x3,          /* alignment = 3 (4-byte aligned) */
    NdrFcShort( 0x10 ),  /* struct size = 16 */
    0x8,          /* FC_LONG (Data1) */
    0x6,          /* FC_SHORT (Data2) */
    0x6,          /* FC_SHORT (Data3) */
    0x4c,         /* FC_EMBEDDED_COMPLEX */
    0x0,          /* padding */
    NdrFcShort( 0xfff1 ), /* Offset back to FC_SMFARRAY (Data4) */
    0x5b,         /* FC_END */
```

## 4. Procedure Format Strings

The procedure format string (`MIDL_PROC_FORMAT_STRING`) describes each method's signature for the NDR interpreter. All methods across all interfaces share a single proc format string blob.

### Oi2 Procedure Header Layout (26 bytes + optional extensions)

Each method starts at a known offset in the format string. The layout for Oi2 interpreted procedures:

```
Offset  Size  Field                          Notes
──────  ────  ─────                          ─────
+0      1     Handle type                    FC_AUTO_HANDLE (0x33) for COM/WinRT
+1      1     Old Oi flags                   0x6c = object | Oi2
+2      4     RPC flags                      Usually 0x00000000
+6      2     Procedure number               vtable slot index (0-based from IUnknown::QI)
+8      2     Stack size                     Total stack bytes for all params + this + retval
+10     2     Client buffer size hint        Max fixed [in] data size in bytes
+12     2     Server buffer size hint        Max fixed [out] data size in bytes
+14     1     Oi2 flags                      See below
+15     1     Parameter count                Including implicit 'this' is NOT counted;
                                             includes retval HRESULT
+16     1     Extension size                 0x0a = 10 bytes (standard extension block)
+17     1     Extension flags                See below
+18     2     Client correlation count       Number of correlation descriptors client-side
+20     2     Server correlation count       Number of correlation descriptors server-side
+22     2     Notify table offset            Usually 0
+24     2     Float/double mask (x64)        For x64 register passing of float args
```

**Total header size:** 26 bytes (with standard 10-byte extension block)

### Old Oi Flags Byte (+1)

| Bit | Hex | Name | Meaning |
|-----|-----|------|---------|
| 2 | `0x04` | `Oi_RPCSS_ALLOC_USED` | Uses RpcSs memory |
| 5 | `0x20` | `Oi_OBJECT_PROC` | This is an object (COM) procedure |
| 6 | `0x40` | `Oi_OBJ_USE_V2_INTERPRETER` | Uses Oi2 interpreter |
| 7 | `0x80` | `Oi_HAS_RPCFLAGS` | RPC flags field present |

**Common value:** `0x6c` = `Oi_OBJECT_PROC | Oi_OBJ_USE_V2_INTERPRETER | Oi_RPCSS_ALLOC_USED`

### Oi2 Flags Byte (+14)

| Bit | Hex | Name | Meaning |
|-----|-----|------|---------|
| 0 | `0x01` | `ServerMustSize` | Server must compute buffer sizes |
| 1 | `0x02` | `ClientMustSize` | Client must compute buffer sizes |
| 2 | `0x04` | `HasReturn` | Method has a return value |
| 3 | `0x08` | `HasPipes` | Uses pipes |
| 4 | `0x10` | `HasAsyncUuid` | Has async UUID |
| 5 | `0x20` | `HasExtensions` | Extension block present |
| 6 | `0x40` | `HasAsyncHandle` | Uses async handle |

**Common values:**
- `0x44` = `HasReturn | HasExtensions` — method with only base-type params
- `0x45` = `ServerMustSize | HasReturn | HasExtensions` — method with [out] complex types
- `0x46` = `ClientMustSize | HasReturn | HasExtensions` — method with [in] complex types
- `0x47` = `ServerMustSize | ClientMustSize | HasReturn | HasExtensions` — both [in] and [out] complex

### Extension Flags Byte (+17)

| Bit | Hex | Name | Meaning |
|-----|-----|------|---------|
| 0 | `0x01` | `HasNewCorrDesc` | New correlation descriptors |
| 1 | `0x02` | `ClientCorrCheck` | Client-side correlation checking |
| 2 | `0x04` | `ServerCorrCheck` | Server-side correlation checking |
| 3 | `0x08` | `HasNotify` | Has notify routine |
| 4 | `0x10` | `HasNotify2` | Has notify2 routine |
| 5 | `0x20` | `HasComplexReturn` | Complex return value |
| 6 | `0x40` | `HasConformanceRange` | Conformance range checking |
| 7 | `0x80` | `HasBigByValueParam` | Large by-value parameter (e.g., GUID) |

**Common values:**
- `0x01` = `HasNewCorrDesc` — standard, no correlation checks
- `0x03` = `HasNewCorrDesc | ClientCorrCheck` — has [out] user-marshal type
- `0x05` = `HasNewCorrDesc | ServerCorrCheck` — has [in] user-marshal type
- `0x07` = `HasNewCorrDesc | ClientCorrCheck | ServerCorrCheck` — both [in] and [out] user-marshal
- `0x81` = `HasNewCorrDesc | HasBigByValueParam` — has large by-value param like GUID

### Procedure Number (vtable slot)

The proc number is the **vtable slot index** counting from the beginning of the vtable:
- `IUnknown::QueryInterface` = slot 0
- `IUnknown::AddRef` = slot 1
- `IUnknown::Release` = slot 2
- `IInspectable::GetIids` = slot 3
- `IInspectable::GetRuntimeClassName` = slot 4
- `IInspectable::GetTrustLevel` = slot 5
- First custom method = slot 3 (IUnknown-derived) or slot 6 (IInspectable-derived)

### Stack Size

On x64, each parameter takes 8 bytes on the stack (pointer or value, padded to 8).
Stack size = `(paramCount + 1) * 8` (the +1 is for the implicit `this` pointer).

### Buffer Size Hints

- **Client buffer size** (`+10`): Sum of fixed-size [in] data. For base types, this is the
  `BufferSize` of the type (e.g., `FC_LONG` = 4, padded). Value `0` if no [in] base types.
  Each base type's contribution: `sizeof(type)` rounded up to alignment + 4 (for NDR padding).
  In practice for x64 COM: `0x10` for two INT32 [in] params, `0x8` for one INT32, etc.
  
- **Server buffer size** (`+12`): Sum of fixed-size [out] data. For `[out, retval] INT32*`:
  value is `0x24` (36 = 4 bytes data + alignment + HRESULT). For `[out] DOUBLE*`: `0x2c` (44).
  The extra bytes account for NDR padding, alignment, and the HRESULT return value.

## 5. Parameter Encoding

After the 26-byte procedure header, each parameter is described by a parameter descriptor.

### Base Type Parameter (6 bytes)

```
Offset  Size  Field
──────  ────  ─────
+0      2     Parameter flags (PARAM_ATTRIBUTES)
+2      2     Stack offset (from stack base, in bytes)
+4      1     FC_* type code
+5      1     0x00 (padding)
```

### Complex Type Parameter (6 bytes)

```
Offset  Size  Field
──────  ────  ─────
+0      2     Parameter flags (PARAM_ATTRIBUTES)
+2      2     Stack offset
+4      2     Type offset (index into TYPE format string)
```

### PARAM_ATTRIBUTES Flags (16-bit field)

| Bit(s) | Name | Description |
|--------|------|-------------|
| 0 | `MustSize` | Runtime sizing required |
| 1 | `MustFree` | Runtime freeing required |
| 2 | `IsPipe` | Pipe parameter |
| 3 | `IsIn` | [in] parameter |
| 4 | `IsOut` | [out] parameter |
| 5 | `IsReturn` | Return value |
| 6 | `IsBasetype` | Simple base type (FC_LONG, etc.) |
| 7 | `IsByValue` | Passed by value (not by pointer) |
| 8 | `IsSimpleRef` | Simple reference (pointer to simple type) |
| 9 | `IsDontCallFreeInst` | Don't call FreeInst |
| 10 | `IsForceAllocate` | Force allocation on server |
| 11 | `SaveForAsyncFinish` | Used for async |
| 12:15 | `ServerAllocSize` | Server allocation size / 8 |

### Common PARAM_ATTRIBUTES Values

| Hex | Binary | Meaning | Usage |
|-----|--------|---------|-------|
| `0x0048` | `IsIn \| IsBasetype` | [in] base type | `[in] INT32 a` |
| `0x0070` | `IsOut \| IsReturn \| IsBasetype` | HRESULT return | Always for retval HRESULT |
| `0x2150` | `IsOut \| IsBasetype \| IsSimpleRef \| ServerAllocSize=8` | [out] base type pointer | `[out, retval] INT32* result` |
| `0x008b` | `MustSize \| MustFree \| IsIn \| IsByValue` | [in] user-marshal by value | `[in] HSTRING name` |
| `0x2113` | `MustSize \| MustFree \| IsOut \| IsSimpleRef \| ServerAllocSize=8` | [out] user-marshal pointer | `[out, retval] HSTRING* name` |
| `0x0013` | `MustSize \| MustFree \| IsOut` | [out] interface pointer | `[out, retval] IInspectable** widget` |
| `0x010a` | `MustFree \| IsIn \| IsSimpleRef` | [in] struct by ref | `[in] GUID id` |

### Parameter Examples from Generated Code

## 6. Proxy Vtable Layout

The proxy vtable uses the `CINTERFACE_PROXY_VTABLE` macro, which expands to a structure with a header (proxy info + IID) followed by vtable function pointers.

### For IUnknown-derived interface (no delegation)

```c
CINTERFACE_PROXY_VTABLE(<total_vtable_slots>) _<InterfaceName>ProxyVtbl = {
    &<InterfaceName>_ProxyInfo,       // MIDL_STUBLESS_PROXY_INFO*
    &IID_<InterfaceName>,              // IID*
    IUnknown_QueryInterface_Proxy,     // slot 0: QI
    IUnknown_AddRef_Proxy,             // slot 1: AddRef
    IUnknown_Release_Proxy,            // slot 2: Release
    (void *) (INT_PTR) -1 /* <InterfaceName>::Method1 */ ,  // slot 3
    (void *) (INT_PTR) -1 /* <InterfaceName>::Method2 */ ,  // slot 4
    ...
};
```

- `(void *) (INT_PTR) -1` is the **stubless proxy marker** — the NDR runtime interprets the format string instead of calling a real function
- `CStdStubBuffer_METHODS` is used for the stub vtable (non-delegating)

### For IInspectable-derived interface (with delegation)

```c
CINTERFACE_PROXY_VTABLE(<total_vtable_slots>) _<InterfaceName>ProxyVtbl = {
    &<InterfaceName>_ProxyInfo,
    &IID_<InterfaceName>,
    IUnknown_QueryInterface_Proxy,     // slot 0
    IUnknown_AddRef_Proxy,             // slot 1
    IUnknown_Release_Proxy,            // slot 2
    0 /* IInspectable::GetIids */ ,         // slot 3: forwarded
    0 /* IInspectable::GetRuntimeClassName */ , // slot 4: forwarded
    0 /* IInspectable::GetTrustLevel */ ,   // slot 5: forwarded
    (void *) (INT_PTR) -1 /* <Iface>::Method1 */ , // slot 6
    ...
};
```

- Forwarded methods use `0` (NULL), not `-1`
- `CStdStubBuffer_DELEGATING_METHODS` is used for the stub vtable (delegating)

### FormatStringOffsetTable

```c
static const unsigned short <InterfaceName>_FormatStringOffsetTable[] = {
    (unsigned short) -1,    // QI (inherited, not in format string)
    (unsigned short) -1,    // AddRef
    (unsigned short) -1,    // Release
    // For IInspectable-derived:
    (unsigned short) -1,    // GetIids
    (unsigned short) -1,    // GetRuntimeClassName
    (unsigned short) -1,    // GetTrustLevel
    // Custom methods:
    0,                      // offset of Method1 in ProcFormatString
    38,                     // offset of Method2
    76,                     // offset of Method3
    ...
};
```

- Inherited methods get `(unsigned short) -1`
- Custom methods get their byte offset into the proc format string

### ProxyInfo and ServerInfo use `[-3]` or `[-6]` offset

```c
static const MIDL_STUBLESS_PROXY_INFO <InterfaceName>_ProxyInfo = {
    &Object_StubDesc,
    <file>__MIDL_ProcFormatString.Format,
    &<InterfaceName>_FormatStringOffsetTable[-3],  // -3 for IUnknown, -6 for IInspectable
    0, 0, 0
};
```

The `[-3]` trick: The NDR runtime indexes the table by vtable slot number. Slots 0-2 are IUnknown methods. By pointing to `table[-3]`, when the runtime accesses `table[3]`, it actually accesses `table[0]` which is the first custom method offset.

For IInspectable-derived interfaces: `[-3]` is still used because the offset table already includes entries for slots 3-5 (the IInspectable methods with value `-1`).

## 7. Stub Vtable Layout

### For IUnknown-derived (non-delegating)

```c
const CInterfaceStubVtbl _<InterfaceName>StubVtbl = {
    &IID_<InterfaceName>,
    &<InterfaceName>_ServerInfo,
    <total_vtable_slots>,           // e.g., 7
    0,                              // pure interpreted (no custom thunks)
    CStdStubBuffer_METHODS          // standard stub buffer methods
};
```

### For IInspectable-derived (delegating)

```c
// Stub dispatch function table
EXTERN_C DECLSPEC_SELECTANY const PRPC_STUB_FUNCTION <InterfaceName>_table[] = {
    STUB_FORWARDING_FUNCTION,       // GetIids → forwarded to base
    STUB_FORWARDING_FUNCTION,       // GetRuntimeClassName → forwarded
    STUB_FORWARDING_FUNCTION,       // GetTrustLevel → forwarded
    NdrStubCall2,                   // Method1 → interpreted via format string
    NdrStubCall2,                   // Method2
    ...
};

CInterfaceStubVtbl _<InterfaceName>StubVtbl = {
    &IID_<InterfaceName>,
    &<InterfaceName>_ServerInfo,
    <total_vtable_slots>,           // e.g., 15
    &<InterfaceName>_table[-3],     // offset by 3 IUnknown methods
    CStdStubBuffer_DELEGATING_METHODS  // delegating stub buffer methods
};
```

- `STUB_FORWARDING_FUNCTION` = base class method forwarding (for IInspectable methods)
- `NdrStubCall2` = NDR interpreter dispatch (for custom methods)
- The function table has entries for slots 3..N (after IUnknown methods)
- The `[-3]` offset works the same as for FormatStringOffsetTable

## 11. WinRT-Specific Patterns

### IInspectable Base Interface

When an interface derives from `IInspectable`, the proxy/stub has these differences from plain IUnknown:

1. **Vtable slots 3-5 are forwarded** (GetIids, GetRuntimeClassName, GetTrustLevel)
2. **Proxy vtable uses `0`** (not `-1`) for forwarded slots
3. **Stub function table uses `STUB_FORWARDING_FUNCTION`** for forwarded slots
4. **Stub vtable uses `CStdStubBuffer_DELEGATING_METHODS`** instead of `CStdStubBuffer_METHODS`
5. **BaseIIDList includes `&IID_IInspectable`** for each delegating interface
6. **Proc numbers start at 6** (after QI=0, AddRef=1, Release=2, GetIids=3, GetRuntimeClassName=4, GetTrustLevel=5)

### FormatStringOffsetTable for IInspectable-derived

```c
static const unsigned short IWidgetProvider_FormatStringOffsetTable[] = {
    (unsigned short) -1,    // slot 3: GetIids (inherited from IInspectable)
    (unsigned short) -1,    // slot 4: GetRuntimeClassName
    (unsigned short) -1,    // slot 5: GetTrustLevel
    0,                      // slot 6: GetWidget
    38,                     // slot 7: SetName
    76,                     // slot 8: GetName
    ...
};
```

Note: The table starts at slot 3 (IUnknown methods 0-2 are handled by the `[-3]` offset trick).

### WinRT Type Mappings

| WinRT Type | NDR FC_* | Notes |
|------------|----------|-------|
| `Boolean` | `FC_SMALL` (0x03) | 1-byte boolean |
| `Int16` | `FC_SHORT` (0x06) | |
| `UInt16` | `FC_USHORT` (0x07) | |
| `Int32` | `FC_LONG` (0x08) | |
| `UInt32` | `FC_ULONG` (0x09) | |
| `Int64` | `FC_HYPER` (0x0B) | |
| `UInt64` | `FC_HYPER` (0x0B) | Same as Int64 |
| `Single` | `FC_FLOAT` (0x0A) | |
| `Double` | `FC_DOUBLE` (0x0C) | |
| `Char16` | `FC_WCHAR` (0x05) | |
| `UInt8` | `FC_BYTE` (0x01) | |
| `String` (HSTRING) | `FC_USER_MARSHAL` (0xB4) | See [Section 12](#12-user-marshal-encoding) |
| `GUID` | `FC_STRUCT` (0x15) | 16-byte structure |
| `Object` (IInspectable) | `FC_IP` (0x2F) | With `FC_CONSTANT_IID` |
| Interface pointer | `FC_IP` (0x2F) | With `FC_CONSTANT_IID` for the specific IID |
| `HRESULT` (return) | `FC_LONG` (0x08) | Always last param |
| Enum (Int32) | `FC_ENUM32` (0x0E) | WinRT enums are 32-bit |
| Struct | `FC_STRUCT` (0x15) | Or `FC_BOGUS_STRUCT` if complex |

## 12. User Marshal Encoding

HSTRING and BSTR use the `FC_USER_MARSHAL` mechanism. The NDR runtime calls user-provided routines to marshal/unmarshal these types.

### User Marshal Routine Table

```c
static const USER_MARSHAL_ROUTINE_QUADRUPLE UserMarshalRoutines[ WIRE_MARSHAL_TABLE_SIZE ] = {
    {
        (USER_MARSHAL_SIZING_ROUTINE)   XFG_TRAMPOLINE_FPTR(HSTRING_UserSize),
        (USER_MARSHAL_MARSHALLING_ROUTINE) XFG_TRAMPOLINE_FPTR(HSTRING_UserMarshal),
        (USER_MARSHAL_UNMARSHALLING_ROUTINE) XFG_TRAMPOLINE_FPTR(HSTRING_UserUnmarshal),
        (USER_MARSHAL_FREEING_ROUTINE)  XFG_TRAMPOLINE_FPTR(HSTRING_UserFree)
    }
};
```

### XFG (Control Flow Guard) Trampolines

```c
XFG_TRAMPOLINES(HSTRING)
```

This macro generates type-safe wrapper functions when `_CONTROL_FLOW_GUARD_XFG` is defined.
When not defined, `XFG_TRAMPOLINE_FPTR(func)` is just `func`.

### FC_USER_MARSHAL Format

```
Byte 0:    0xB4 (FC_USER_MARSHAL)
Byte 1:    flags (0x83 = unique pointer | alignment 3)
Bytes 2-3: user marshal table index (usually 0)
Bytes 4-5: user type memory size (8 on x64 for pointers)
Bytes 6-7: user type buffer size (0 = variable size)
Bytes 8-9: offset to wire representation descriptor
```

### HSTRING Wire Representation

On the wire, HSTRING is marshalled as:
```
struct {
    ULONG length;     // character count
    ULONG alloc;      // allocated character count
    WCHAR data[];     // conformant array of WCHAR
};
```

This is described in the type format string as:
1. `FC_UP` → points to `FC_CSTRUCT`
2. `FC_CSTRUCT` (conformant structure with trailing `FC_CARRAY` of `FC_SHORT`)

## 13. Symbol Model to NDR Mapping

### InterfaceSymbol → Per-Interface NDR Structures

| Symbol Property | NDR Structure | Notes |
|----------------|---------------|-------|
| `InterfaceSymbol.Uuid` | IID in proxy/stub vtable | `&IID_<Name>` |
| `InterfaceSymbol.RequiredInterfaces` | BaseIIDList entry | Determines delegation |
| `InterfaceSymbol.Members` | FormatStringOffsetTable entries | One entry per method |
| `InterfaceSymbol.Name` | InterfaceNamesList entry | String name |

### MethodSymbol → Procedure Format String

| Symbol Property | Proc Format Field | Notes |
|----------------|-------------------|-------|
| vtable index | Proc number (+6) | Offset from IUnknown slot 0 |
| `MethodSymbol.Parameters` | Parameter descriptors | 6 bytes each |
| `MethodSymbol.ReturnType` | Return param descriptor | Always HRESULT in COM/WinRT |
| `MethodSymbol.Parameters.Count + 1` | Param count byte | +1 for retval |

### ParameterSymbol → Parameter Descriptor

| Symbol Property | Param Descriptor Field | Notes |
|----------------|----------------------|-------|
| `ParameterSymbol.Direction` | PARAM_ATTRIBUTES flags | In/Out/InOut |
| `ParameterSymbol.Type` | FC_* code or type offset | Base types inline, complex via offset |
| stack position | Stack offset | `(index + 1) * 8` on x64 |

### TypeRef → FC_* Format Code

| TypeRef.Name | FC_* Code | IsBasetype? |
|-------------|-----------|-------------|
| `Boolean` | `FC_SMALL` (0x03) | Yes |
| `Int16` | `FC_SHORT` (0x06) | Yes |
| `UInt16` | `FC_USHORT` (0x07) | Yes |
| `Int32` | `FC_LONG` (0x08) | Yes |
| `UInt32` | `FC_ULONG` (0x09) | Yes |
| `Int64` | `FC_HYPER` (0x0B) | Yes |
| `UInt64` | `FC_HYPER` (0x0B) | Yes |
| `Single` | `FC_FLOAT` (0x0A) | Yes |
| `Double` | `FC_DOUBLE` (0x0C) | Yes |
| `Char16` | `FC_WCHAR` (0x05) | Yes |
| `UInt8` | `FC_BYTE` (0x01) | Yes |
| `String` | `FC_USER_MARSHAL` (0xB4) | No (complex) |
| `Guid` | `FC_STRUCT` (0x15) | No (complex) |
| `Object` | `FC_IP` (0x2F) | No (complex) |
| Interface ref | `FC_IP` (0x2F) | No (complex) |
| `void` | N/A | N/A (no param) |

### PropertySymbol → Method Pairs

Each property generates 1-2 methods in the vtable:

| Property | Generated Methods |
|----------|------------------|
| `get X` → `HRESULT get_X([out, retval] T* value)` | 1 proc format entry |
| `set X` → `HRESULT put_X([in] T value)` | 1 proc format entry |
| Read-write property | Both get + put |
| Read-only property | Only get |

### EventSymbol → Method Pairs

Each event generates 2 methods:

| Event | Generated Methods |
|-------|------------------|
| `add_<Event>` → `HRESULT add_<Event>([in] <DelegateType> handler, [out, retval] EventRegistrationToken* token)` | |
| `remove_<Event>` → `HRESULT remove_<Event>([in] EventRegistrationToken token)` | |

### RuntimeClassSymbol → Multiple Interfaces

A runtime class generates proxy/stubs for each of its interfaces (default, factory, statics, etc.),
but the class itself doesn't appear in the proxy/stub file. Only its interfaces do.

## Appendix A: NdrFcShort and NdrFcLong Macros

These macros encode multi-byte values in little-endian format:

```c
#define NdrFcShort(s) (unsigned char)(s & 0xff), (unsigned char)(s >> 8)
#define NdrFcLong(s)  (unsigned char)(s & 0xff), (unsigned char)((s & 0x0000ff00) >> 8), \
                      (unsigned char)((s & 0x00ff0000) >> 16), (unsigned char)((s & 0xff000000) >> 24)
```

## Appendix C: Implementation Checklist for StubEmitter

1. **Type Format String Builder**
   - Track all unique complex types (HSTRING, GUID, interface pointers)
   - Assign offsets as types are registered
   - Emit FC_RP/FC_UP/FC_OP pointer wrappers
   - Emit FC_USER_MARSHAL entries for HSTRING
   - Emit FC_STRUCT entries for GUID
   - Emit FC_IP + FC_CONSTANT_IID for interface pointers
   - Handle both [in] and [out] variants of user-marshal types

2. **Proc Format String Builder**
   - For each interface, for each method:
     - Compute vtable slot number
     - Compute stack size (`(params.Count + 2) * 8` for this + params + retval)
     - Compute Oi2 flags based on param types
     - Compute extension flags based on user-marshal usage
     - Emit 26-byte procedure header
     - Emit 6-byte parameter descriptor for each param
     - Emit 6-byte return value descriptor (always FC_LONG for HRESULT)

3. **Per-Interface Structures**
   - FormatStringOffsetTable (with -1 for inherited methods)
   - MIDL_STUBLESS_PROXY_INFO
   - MIDL_SERVER_INFO
   - CINTERFACE_PROXY_VTABLE
   - Stub function table (if delegating)
   - CInterfaceStubVtbl

4. **File-Level Structures**
   - MIDL_STUB_DESC
   - ProxyVtblList
   - StubVtblList
   - InterfaceNamesList
   - BaseIIDList (if any delegating)
   - IID_Lookup function
   - ExtendedProxyFileInfo

5. **User Marshal Support**
   - XFG trampoline macros
   - USER_MARSHAL_ROUTINE_QUADRUPLE table
   - Per-type: HSTRING_UserSize/Marshal/Unmarshal/Free

6. **File Boilerplate**
   - Platform guard (#if defined(_M_AMD64))
   - Warning pragmas
   - USE_STUBLESS_PROXY define
   - rpcproxy.h include + version check
   - Size defines (computed after all format strings built)
