Built with AI at the Speed of Light

The MIDL Pain

  • Legacy compiler — 30+ years old, native C++, opaque internals
  • No Language Server Protocol support whatsoever
  • No editor integration — syntax highlighting only via basic TextMate grammar
  • Cryptic error messages with poor source positions
  • Slow iteration: edit → compile → squint at errors → repeat
  • No autocomplete, no hover, no go-to-definition
  • Cannot partially analyze incomplete files

What Changed?

  • Previous efforts improved things incrementally but never rewrote from scratch
  • AI changes the equation: infinite intelligence on tap

Design Principles

Roslyn-Style Red-Green Tree
Immutable, fully-faithful, lossless syntax tree. Every token and trivia is preserved — round-trips perfectly.
Error Recovery
Parser never throws. Every input — no matter how broken — produces a complete syntax tree.
LSP-First
Designed for editor integration from day one. Diagnostics, completions, hovers — not bolted on.
NativeAOT
3.6 MB single-file binary. 14 ms warm compile. No .NET runtime required at deployment.
.NET 10 / C#
Team accessibility. System.Reflection.Metadata for WinMD emit. Modern language features throughout.

Feature Overview

MIDL3 Syntax

  • namespace, runtimeclass, interface, delegate, struct, enum, apicontract
  • Properties { get; set; }, constructors, events
  • static, partial, unsealed, protected, overridable
  • Generics: IVector<String>, >> disambiguation
  • Forward declarations
  • User-defined attributes with [attributeusage]

Classic MIDL (Compat Mode)

  • coclass, library, typedef, union, dispinterface
  • HRESULT + [in]/[out]/[retval]
  • Pointer types, cpp_quote
  • Win32 type aliases
